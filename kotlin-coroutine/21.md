# 21장 플로우 만들기

## 원시값을 가지는 플로우

```kotlin
suspend fun main() {
    flowOf(1,2,3,4,5)
        .collect { print(it) } // 12345
        
    emptyFlow<Int>()
        .collect { print(it) } // 아무것도 출력되지 않음
}
```

## 컨버터 asFlow

Iterable, Iterator, Sequence를 Flow로 바꿀 수 있다

```kotlin
suspend fun main() {
    listO(1,2,3,4,5) // 또는 setOf(), sequnceOf()
        .asFlow() 
        .collect { print(it) } // 12345
}
```

## 함수를 플로우로 바꾸기

#### 중단 함수를 플로우로 변경하기

중단 함수의 결과가 플로우의 유일한 값이 된다

```kotlin
suspend fun main() {
    val function = suspend {
        delay(1000)
        "UserName"
    }
    
    function.asFlow()
        .collect { print(it) }
}

// (1초 후)
// UserName
```

#### 일반함수를 플로우로 변경하기

함수의 참조값을 사용해서 플로우로 변경할 수 있다

```kotlin
suspend fun getUserName(): String {
    delay(1000)
    return "UserName"
}

suspend fun main() {
    ::getUserName
        .asFlow()
        .collect { println(it) }
}

// (1초 후)
// UserName
```

## 플로우 빌더

flow 함수를 먼저 호출하고, 람다식 내부에서 emit 함수를 사용해서 다음 값을 방출한다

* 모든 값을 방출하기 위해서 emitAll을 사용할 수도 있음

```kotlin
fun makeFlow() = flow {
    repeat(3) { num ->
        delay(1000)
        emit(num)
    }
}

suspend fun main() {
    makeFlow()
        .collect { println(it) }
}

// (1초 후)
// 0
// (1초 후)
// 1
```

## 플로우 빌더 이해하기

```kotlin
public fun <T> flowOf(vararg elements: T) = flow {
    for (element in elements) {
        emit(element)
    }
}
```

#### collect 메서드 내부에서 block 함수를 호출하는 Flow 인터페이스 구현

```kotlin
fun <T> flow(
    block: suspend FlowCollector<T>.() -> Unit // 전달
): Flow<T> = object: Flow<T>() {
    override suspend fun collect(collector: FlowCollector<T>) {
        collector.block() // 전달받은 람다 호출
    }
}

interface Flow<out T> {
    suspend fun collect(collector: FlowCollector<T>)
}

fun interface FlowCollector<in T> {
    suspend fun emit(value: T)
}
```

#### 원리 이해해보기

collect를 호출하면 1에서 정의한 람다식 실행 > emit을 호출하면 2에서 정의된 람다신 호출

```kotlin
fun main() = runBlocking {
    flow { // 1 flow 빌더를 호출하면 단지 객체를 만들 뿐
        emit("A") // emit 함수의 본체는 println(value)
        emit("B")
        emit("C")
    }.collect { value -> // 2 collect 호출 시에는 collector 인터페이스의 block 함수를 호출
        println(value)
    }
}

// A
// B
// C
```

## 채널 플로우 channelFlow

flow -  콜드 데이터 스트림 / 필요할 때만 지연 요청

```kotlin
data class User(val name: String)

interface UserApi {
    suspend fun takePage(pageNumber: Int): List<User>
}

class FakeUserApi: UserApi {
    private val users = List(20) { User("User$it") }
    private val pageSize = 3

    override suspend fun takePage(
        pageNumber: Int
    ): List<User> {
        delay(1000) // 중단 함수
        return users
            .drop(pageSize * pageNumber)
            .take(pageSize)
    }
}

fun allUsersFlow(api: UserApi) = flow { // flow
    var page = 0
    do {
        println("Fetcing page $page")
        val users = api.takePage(page++) // 중단 함수
        emitAll(users.asFlow())
    } while (!users.isNullOrEmpty())
}

suspend fun main() {
    val api = FakeUserApi()
    val users = allUsersFlow(api)
    val user = users.first {
            println("Checking $it")
            delay(1000) // 중단 함수
            it.name == "User3"
        }
    println(user)
}

// 유저 정보를 확인하고 다음 페이지 요청
Fetcing page 0
// (1초 후)
Checking User(name=User0)
// (1초 후)
Checking User(name=User1)
// (1초 후)
Checking User(name=User2)
// (1초 후)
Fetcing page 1
// (1초 후)
Checking User(name=User3)
// (1초 후)
User(name=User3)
```

#### channelFlow - channel + flow 데이터를 생성하고 소비하는 과정이 별개로 진행된다

#### 원소를 처리하고 있을 때 페이지 받기

```kotlin
fun allUsersFlow(api: UserApi) = channelFlow { // channelFlow
    var page = 0
    do {
        println("Fetching page $page")
        val users = api.takePage(page++) // 중단 함수
        users?.forEach { send(it) } // emit 대신 send 사용
    } while (!users.isNullOrEmpty())
}

suspend fun main() {
    val api = FakeUserApi()
    val users = allUsersFlow(api)
    val user = users.first {
            println("Checking $it")
            delay(1000) // 중단 함수
            it.name == "User3"
        }
    println(user)
}

// (1초 후)
Checking User(name=User0)
Fetcing page 1
// (1초 후)
Checking User(name=User1)
Fetcing page 2
// (1초 후)
Checking User(name=User2)
Fetcing page 3
// (1초 후)
Checking User(name=User3)
Fetcing page 4
```

## 콜백플로우

변경 이벤트를 감지해야 할 경우 사용

감지 프로세스는 이벤트 처리 프로세스와 독립적이어야 하므로 channelFlow를 사용해도 좋지만, callbackFlow가 더 적합

* 거의 비슷한 동작이지만 callbackFlow가 콜백을 사용할 때 에러에 덜 민감하도록 추가 처리가 되어 있음
* ex) awaitClose {} - 콜백을 등록하고 채널이 닫힐 때 까지 중단되는 함수 / 코루틴이 종료되는 것을 막음

```kotlin
fun fowFrom(api: CallBasedApi) = callbackFlow {
    val callback = object: Callback {
        override fun onNextValue(value: T) {
            trySendBlocking(value)
        }
        override fun onApiError(cause: Throwable) {
            cancel(CancellationException("API Error", cause))
        }
        override fun onCompleted() = channel.close()
    }
    api.register(callback)
    awaitClose { api.unregister(callback) }
}
```
